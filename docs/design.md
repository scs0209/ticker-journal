## Problem Statement

React Native를 만들면서 배우고, 이력서에 “모바일(스토어 배포) 가능”을 보여주고 싶다. 동시에 본인이 실제로 쓸 유틸이어야 한다.

현재는 주식 리서치·매매 이유가 **노션/메모장 + 엑셀/구글시트**에 흩어진다. 폰에서 앱 내 폼으로 빠르게 넣고, 웹에서 정리·검색하고, 종목 단위 타임라인으로 묶인 곳이 없다.

## What Makes This Cool

종목 하나를 열면 **차트(WebView) 아래**에 내가 저장한 링크·메모·매매 이유가 한 타임라인으로 붙는다. “증권앱의 차트”와 “노션의 스크랩”이 한 화면에서 만난다. v2에서는 그 기록이 AI 주간 브리핑으로 요약된다.

## Constraints

- 목적: Learning + Having fun + 이력서(모바일·웹 연계·스토어)
- 도메인: 주식 리서치 저널 (스크랩 + 기록)
- 아키텍처: RN 네이티브 셸 + WebView(차트) + Next 웹, 같은 계정·같은 DB
- 스토어: App Store **및** Play Store 등록이 성공 조건
- AI 주간 브리핑·브로커 연동·공유 시트: MVP 밖 (v1.1 / v2)
- MVP 입력 경로: 앱 FAB → 메모/링크/매매 폼 (공유 시트는 v1.1)

## Premises

1. 학습·포트폴리오용이지 Tradervue급 매매분석 SaaS가 아니다.
2. MVP 핵심: 종목 타임라인(링크/메모/매매 이유) + 웹·앱 동일 계정 + 차트 WebView. AI 브리핑은 v2.
3. 차트/시세는 WebView·임베드. RN은 네비·인증·리스트/상세·입력.
4. 스토어 등록이 성공 조건이므로 기능은 얇게, 심사 상태(빈 목록·에러·로그아웃·계정 삭제)를 먼저 갖춘다.

## Implementation Blockers (코딩 전 결정)

아래 3건을 ADR 1페이지로 고르기 전에는 Next Steps 2 이후 착수하지 않는다.

| # | 결정 | MVP 기본안 (권장) | 대안 |
|---|------|-------------------|------|
| B1 | Auth | **Supabase Auth + 이메일 매직링크**, 웹·앱 동일 프로젝트. 앱은 Expo Linking / universal link로 세션 수신 | Firebase Auth |
| B2 | 차트 | **TradingView 심볼 위젯을 WebView로**, 고정 높이. 실패 시 “차트 열기” 외부 링크 fallback | 정적 placeholder만 |
| B3 | 티커 스키마 | MVP는 **`market` + `symbol`** (`US`/`KR`). 표시명 `name` optional. 차트는 우선 **US만 위젯**, KR은 타임라인만(차트 fallback 링크) | US-only로 더 축소 |

## Data model (MVP)

### `tickers`
- `id`, `user_id`, `market` (`US`|`KR`), `symbol` (예: `AAPL`, `005930`), `name` (nullable), `created_at`
- Unique: `(user_id, market, symbol)`
- 수명: 사용자가 추가 / 삭제(관련 entries cascade 또는 soft-delete — cascade 권장)

### `entries`
공통: `id`, `user_id`, `ticker_id`, `type`, `created_at`, `updated_at`

| type | 필수 필드 | 선택 |
|------|-----------|------|
| `memo` | `body` (text) | — |
| `link` | `url` | `title`, `note` |
| `trade` | `side` (`buy`\|`sell`), `traded_at` | `price`, `qty`, `reason` (text) |

CRUD: Create / Read / Update / Delete 모두 MVP. 웹·앱 동일 API.

### Timeline / Search
- 앱 타임라인 필터: **type chips** (`all`\|`memo`\|`link`\|`trade`) + **최신순**만
- 웹 “아카이브” 정의: **과거 entries 검색·조회** (삭제 보관함이 아님)
- 웹 검색 MVP: `q`가 `entries.body|note|reason|title|url` 및 ticker symbol/name에 ILIKE. 결과 = entry 리스트 → 종목 상세 링크. 페이지 크기 20

## Screen inventory

**앱 (3 + 인증)**
1. 관심종목 목록 (+ 추가, 빈/에러/로딩)
2. 종목 상세: 고정 높이 WebView + FlatList 타임라인 + FAB → 작성(바텀시트/모달)
3. (모달) 엔트리 작성·수정
4. 로그인 / 로그아웃 / 계정 삭제 진입

**웹 (MVP = 조회 + 가벼운 작성)**
1. 로그인
2. 검색 홈 (= 아카이브 진입, read 중심)
3. 종목 상세: 타임라인 조회 + **엔트리 추가/수정/삭제** (앱과 동일 폼). 차트는 앱과 같이 **TradingView embed**, KR은 fallback 링크

와이어프레임(앱 목록·상세 + 웹 검색): `docs/assets/ticker-journal-wireframe.png`

상세 레이아웃(앱): 차트 **고정 높이** + 타임라인 FlatList + 입력은 **bottom sheet** (WebView nested scroll 충돌 회피).

## Auth flow (sequence)

1. 웹 또는 앱에서 이메일 입력 → Supabase magic link 발송
2. 링크 클릭 → 웹이면 세션 쿠키/스토리지, 앱이면 `tickerjournal://auth/callback` (또는 universal link) → session set
3. 이후 API는 Supabase JWT (RLS: `user_id = auth.uid()`)

### 계정 삭제 (스토어 필수)

1. 설정 → “계정 삭제” → 확인 다이얼로그(되돌릴 수 없음 명시)
2. `tickers` / `entries` 사용자 행 삭제 (DB cascade on `user_id` 또는 RPC)
3. Supabase `auth.admin.deleteUser` 또는 클라이언트 지원 삭제 API 호출
4. 로컬 세션 clear → 로그인 화면
5. 웹 설정에도 동일 경로 제공

## Monorepo skeleton

```
ticker-journal/
  apps/mobile/          # Expo Router
  apps/web/             # Next.js App Router
  packages/shared/      # zod schemas + types for tickers/entries
  package.json          # pnpm workspaces
  turbo.json            # optional but recommended
```

통신: Supabase JS 클라이언트 직접 + RLS (별도 REST 서버 없이 MVP). `packages/shared`에 zod로 폼·insert 검증.

## Approaches Considered

### Approach A: Expo 쐐기 + 한쪽 스토어
빠름. **현재 Success Criteria(양 스토어)와 불일치 → 기각.**

### Approach B / B-lite: 모노레포 웹+앱 (채택)
Expo + Next + 공유 스키마. 기능은 얇게, 스토어 둘 다. iOS→Android 순 제출 가능.

### Approach C: WebView 셸
웹 재활용 최대. RN 학습·면접 어필 약함 → 기각.

## Recommended Approach

**B-lite** + 위 데이터모델/블로커 기본안.

단계화:
- **Phase 0:** 모노레포 + Supabase + 앱 목록/상세/CRUD (US 차트)
- **Phase 1:** 웹 로그인·검색·종목 상세
- **Phase 2:** 프라이버시 정책·데모 계정·EAS Submit → 양 스토어

## Success Criteria

- [ ] 실사용 관심종목 ≥3, 앱으로 memo/link/trade 입력 후 웹 검색으로 회수
- [ ] 2분 데모: 로그인 → 목록 → 상세(WebView+타임라인) → 웹 동일 기록
- [ ] App Store + Play Store 리스팅(또는 승인 빌드) 존재
- [ ] 이력서 스택: Expo/RN, Next.js, Supabase, WebView, 스토어 배포

## The Assignment

코딩 전: 노션/시트에서 **실제 종목 3개**(가능하면 US 2 + KR 1)를 고르고, 종목당 샘플 entry 5줄(memo/link/trade 혼합)을 적는다. 그 샘플로 `market+symbol` 스키마와 zod가 통과하는지 확인한다. 완료물 = 샘플 마크다운 1파일 또는 ADR에 붙인 표.
